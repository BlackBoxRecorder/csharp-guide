# 设计模式

设计模式（Design Pattern）是解决特定场景下重复出现问题的成熟方案，是前人在大量工程实践中总结出的经验结晶。本栏目收录 21 种经典 GoF 设计模式，每篇文档包含模式意图、核心结构、C# 代码示例、典型应用场景与总结。示例代码位于仓库 `src/DesignPatterns` 目录，每个模式一个独立工程，可对照文档单独编译运行。

## 创建型模式

创建型模式关注对象的创建机制，使创建逻辑与使用逻辑解耦。

| 模式 | 意图 | 文档 |
| :--- | :--- | :--- |
| Abstract Factory（抽象工厂） | 创建一组相关或依赖的对象家族，无需指定具体类 | [阅读文档](./abstract-factory) |
| Builder（建造者） | 分步构建复杂对象，将构造过程与表示分离 | [阅读文档](./builder) |
| Factory Method（工厂方法） | 将对象创建延迟到子类，由子类决定实例化哪个类 | [阅读文档](./factory-method) |
| Prototype（原型） | 通过复制现有实例创建新对象，避免重复初始化 | [阅读文档](./prototype) |
| Singleton（单例） | 确保一个类只有一个实例，并提供全局访问点 | [阅读文档](./singleton) |

## 结构型模式

结构型模式关注类与对象的组合方式，形成更大的结构。

| 模式 | 意图 | 文档 |
| :--- | :--- | :--- |
| Adapter（适配器） | 将不兼容的接口转换为客户端期望的接口 | [阅读文档](./adapter) |
| Bridge（桥接） | 将抽象与实现分离，使两者可以独立变化 | [阅读文档](./bridge) |
| Composite（组合） | 将对象组织成树形结构，使单个对象与组合对象使用一致 | [阅读文档](./composite) |
| Decorator（装饰器） | 动态地为对象添加职责，比继承更灵活 | [阅读文档](./decorator) |
| Facade（外观） | 为复杂子系统提供统一的高层接口 | [阅读文档](./facade) |
| Flyweight（享元） | 共享细粒度对象，减少内存占用 | [阅读文档](./flyweight) |
| Proxy（代理） | 为对象提供替身，控制对其的访问 | [阅读文档](./proxy) |

## 行为型模式

行为型模式关注对象之间的职责分配与通信。

| 模式 | 意图 | 文档 |
| :--- | :--- | :--- |
| Chain of Responsibility（责任链） | 将请求沿处理链传递，直到有对象处理它 | [阅读文档](./chain-of-responsibility) |
| Command（命令） | 将请求封装为对象，支持撤销、重放与排队 | [阅读文档](./command) |
| Iterator（迭代器） | 顺序访问集合元素，而不暴露内部表示 | [阅读文档](./iterator) |
| Mediator（中介者） | 通过中介对象简化对象间的交互 | [阅读文档](./mediator) |
| Observer（观察者） | 定义一对多依赖，状态变化时自动通知订阅者 | [阅读文档](./observer) |
| State（状态） | 对象内部状态变化时改变其行为 | [阅读文档](./state) |
| Strategy（策略） | 定义一系列算法并封装，使它们可以互相替换 | [阅读文档](./strategy) |
| Template Method（模板方法） | 定义算法骨架，将步骤延迟到子类实现 | [阅读文档](./template-method) |
| Visitor（访问者） | 在不修改类的前提下为类层次增加新操作 | [阅读文档](./visitor) |

## 学习建议

- 从**创建型模式**入手，理解"针对接口编程"的思想，再学习结构型与行为型模式。
- 抽象工厂与工厂方法在仓库 `FactoryPattern` 工程中组合演示，可对照阅读。
- 状态模式与策略模式结构相似但意图不同，建议对比学习；装饰器与代理结构相似，注意区分。
- 每个模式工程均含 `Program.cs` 演示入口，动手运行一遍胜过读十遍。
