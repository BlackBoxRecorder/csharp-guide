要理解数据在网络中如何"寻路"和"可靠传输"，先要看懂 IP 头和 TCP 头。当你在 C# 里调用 `Send` 后，数据在操作系统内核中是这样一层层打包的：

```text
你的数据 → [TCP 头] → [IP 头] → [以太网头] → 变成电信号发出去
```

**IP 头负责"把包裹送到哪台机器"（网络层寻址），TCP 头负责"送到机器的哪个程序，以及怎么保证可靠"（传输层控制）。**

## IP 头

IP 头的长度通常是 **20 字节**（没有选项的情况下），核心任务是**路由寻址**和**分片**。

| 字段 | 大小 | 作用说明 |
| :--- | :--- | :--- |
| 版本（Version） | 4 bit | IPv4 还是 IPv6，目前绝大多数还是 4。 |
| 头部长度（IHL） | 4 bit | IP 头有多长（单位是 4 字节），因为有可选字段所以需要指明，通常是 5（即 5×4=20 字节）。 |
| 服务类型（Type of Service） | 8 bit | 以前用来标记优先级，现在多用于 QoS（比如区分视频流和普通网页）。 |
| 总长度（Total Length） | 16 bit | 整个 IP 包的总字节数（IP 头 + TCP 头 + 数据），最大 65535 字节。 |
| 标识（Identification） | 16 bit | 一个包的 ID。如果大包被分片，所有分片都带同一个 ID，方便接收端重组。 |
| 标志（Flags） | 3 bit | 控制分片。最重要的是 **DF（Don't Fragment）** 位：置 1 表示"不许分片"，包太大过不了网络就直接丢弃。 |
| 片偏移（Fragment Offset） | 13 bit | 包被分片时表示"我是原数据的第几块"，用于重组顺序。 |
| TTL（Time To Live） | 8 bit | 生存时间。每经过一个路由器减 1，减到 0 时路由器丢弃该包并返回超时 ICMP 消息，防止包在网络里无限循环。 |
| 协议（Protocol） | 8 bit | 告诉接收端 IP 头后面封装的是什么协议：6 代表 TCP，17 代表 UDP，1 代表 ICMP（Ping）。 |
| 头部校验和（Header Checksum） | 16 bit | 只校验 IP 头本身有没有出错，数据部分由 TCP 负责校验。 |
| 源 IP 地址 | 32 bit | 发送方的 IP 地址。 |
| 目的 IP 地址 | 32 bit | 接收方的 IP 地址。 |
| 选项（Options） | 可变 | 很少用，比如记录路由路径、时间戳等。 |

## TCP 头

TCP 头的长度通常是 **20 字节**（没有选项的情况下），它是 TCP 可靠性、流量控制、拥塞控制的核心。

| 字段 | 大小 | 作用说明 |
| :--- | :--- | :--- |
| 源端口（Source Port） | 16 bit | 发送方程序的端口号（比如你的 C# 程序用的 54321）。 |
| 目的端口（Destination Port） | 16 bit | 接收方程序的端口号（比如服务器的 80 或 8080）。 |
| 序列号（Sequence Number） | 32 bit | 这个包里第一个字节的编号。它是字节流的序号，不是包序号，详见"序列号与字节流"一篇。 |
| 确认号（Acknowledgment Number） | 32 bit | 我期望你下一次发送时序列号从哪个数字开始，表示"这个数字之前的所有字节我都收到了"。 |
| 头部长度（Data Offset） | 4 bit | TCP 头有多长（单位是 4 字节），因为有选项字段所以需要指明，通常是 5（20 字节）。 |
| 保留位（Reserved） | 3 bit | 留着以后用，必须为 0。 |
| 控制标志位（Flags） | 9 bit | 6 个核心标志位，每个 1 bit，控制 TCP 的连接状态：<br>• **URG**：紧急指针有效（很少用）。<br>• **ACK**：确认号有效。除了第一次握手，几乎所有包都会带这个位。<br>• **PSH**：推送位，告诉接收端"别等缓冲区满了，赶紧把数据交给应用层"。<br>• **RST**：重置连接，直接粗暴断开，比如端口没监听时收到的包。<br>• **SYN**：同步序列号，用于三次握手建立连接。<br>• **FIN**：请求断开连接，用于四次挥手。 |
| 窗口大小（Window Size） | 16 bit | 流量控制的核心。告诉对方"我现在接收缓冲区还有多少空闲空间，你最多只能发这么多字节过来"。 |
| 校验和（Checksum） | 16 bit | 校验整个 TCP 段（TCP 头 + 数据）。校验失败会被直接丢弃，等待重传。 |
| 紧急指针（Urgent Pointer） | 16 bit | 配合 URG 标志使用，指出紧急数据的末尾位置，实际中极少使用。 |
| 选项（Options） | 可变 | 非常重要，见下文。 |

## TCP 选项：隐藏的"高级功能"

TCP 选项最多 40 字节，里面藏着很多关键机制：

1. **MSS（Maximum Segment Size）**：在三次握手时发送，告诉对方"我这边能接收的最大 TCP 数据部分是 1460 字节，你发的时候别超过这个大小"。这就是分包大小的硬限制来源。
2. **窗口扩大因子（Window Scale）**：窗口大小字段只有 16 bit，最大 65535 字节，在高速网络里太小。这个选项允许把窗口大小左移 N 位（比如乘以 256），让窗口可以大到 1GB。
3. **SACK（选择性确认）**：默认情况下 TCP 只能确认连续的数据——比如发了 1-1000、1001-2000、2001-3000，中间的 1001-2000 丢了，接收端只能回复"我收到 1000 了"，发送端要把 1001-3000 全部重传。SACK 允许接收端说"我收到了 1-1000 和 2001-3000，就是 1001-2000 没收到"，发送端只重传丢的那块，节省带宽。
4. **时间戳（Timestamp）**：用来精确计算 RTT（往返时间），从而更精准地设置重传超时时间；还能防止"序列号回绕"（序列号用完了又从 0 开始，时间戳可以区分新旧包）。

## 一个完整的数据包长什么样

假设你在 C# 里 `Send("Hi")`，最终在网络上飞的数据大概长这样：

```text
[ 以太网头: 14字节 ]  ← 谁发的、谁收的、里面是 IP 还是 ARP
[ IP 头: 20字节 ]     ← 源IP: 192.168.1.100, 目的IP: 8.8.8.8, TTL: 64, 协议: 6(TCP)
[ TCP 头: 20字节 ]    ← 源端口: 54321, 目的端口: 80, 序列号: 1001, ACK: 2001, 标志: PSH+ACK, 窗口: 65535
[ 数据: 2字节 ]       ← "H" "i" (ASCII: 0x48 0x69)
```

## 总结对比

| 对比项 | IP 头 | TCP 头 |
| :--- | :--- | :--- |
| 核心任务 | 找到目标机器（寻址、路由） | 找到目标程序（端口），保证数据可靠、有序 |
| 有没有"连接"概念 | 无，每个包独立路由 | 有，三次握手、四次挥手 |
| 有没有重传机制 | 无，丢了就丢了 | 有，靠序列号、确认号、超时重传 |
| 有没有流量控制 | 无 | 有，靠窗口大小 |
| 校验范围 | 只校验 IP 头本身 | 校验整个 TCP 段（头 + 数据） |
