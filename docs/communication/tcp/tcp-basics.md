TCP 通信涉及多个基础概念，理解它们有助于掌握后面的握手、挥手与可靠性机制。

## IP 与端口

TCP 通信前必须先定位通信对象：

- **IP 地址**：标识网络中的一台主机（如 `192.168.1.100`）。IPv4 为 32 位地址，IPv6 为 128 位地址。
- **端口**：标识主机上的一个具体进程，范围 0 ~ 65535。常见端口如 80（HTTP）、443（HTTPS）、22（SSH）；1024 以下的知名端口通常需要系统权限，客户端一般使用 49152 ~ 65535 的动态端口。
- **四元组**：一个 TCP 连接由源 IP、源端口、目标 IP、目标端口唯一确定。服务端监听固定端口等待连接，客户端用随机端口发起连接，因此一台服务器可以同时维持大量连接。

## Socket 与操作系统

- TCP 协议本身由操作系统内核中的协议栈实现，应用程序并不直接构造报文，而是通过 Socket（套接字）接口与内核交互。
- 应用程序调用 Send/Receive 时，真正的拆包、编号、确认、重传、拥塞控制等工作都由内核协议栈完成。
- 每个连接在内核中对应一个 Socket，由四元组标识；C# 中的 `TcpClient`、`TcpListener` 和 `Socket` 类都是对系统 Socket API 的封装。

## 缓冲区

- 每个 TCP 连接在内核中都维护两个独立的缓冲区：发送缓冲区和接收缓冲区。
- 发送时，应用数据先写入发送缓冲区，内核按合适的大小分片发送；已发送但未收到 ACK 的数据会保留在缓冲区中，以便超时后重传。
- 接收时，内核把收到的数据放进接收缓冲区，应用从中读取。如果应用读取太慢，缓冲区被填满，内核会通过"窗口"机制告知对方暂停发送，防止数据溢出——这就是背压。
- 缓冲区大小可配置（如 `SO_SNDBUF` / `SO_RCVBUF`），设置过小会降低吞吐，过大则浪费内存，通常需要按场景调优。

## 超时

TCP 依赖各种超时机制来应对网络异常：

- **连接超时**：客户端发起 connect 后，若 SYN 多次重传仍未收到响应，最终会放弃连接并报错（如常见的 "Connection timed out"）。
- **空闲超时**：连接长时间没有数据传输时，可通过 TCP KeepAlive 或应用层心跳探测对方是否存活，超时后主动关闭连接以释放资源。
- **重传超时（RTO）**：发送数据后在规定时间内未收到 ACK 就会重传；RTO 会根据网络往返时间（RTT）动态调整，网络越差，超时时间越长。
